PHASE 2 — DESIGN THE MOTION TEMPLATE

Create one polished template named "The Red Thread".

ART DIRECTION:
- Warm ivory and textured paper.
- Deep black editorial compositions.
- Restrained vermilion-red accents.
- Bold typography with dramatic differences in size, weight, alignment, and spacing.
- Subtle grain, print imperfections, drawn lines, stamps, and original geometric illustrations.
- Asymmetrical layouts and deliberate negative space.
- Physically convincing movement with anticipation, inertia, impact, overshoot, and follow-through.

ANIMATION SYSTEM:

1. Phrase reveals using masks, clipping, ink-like reveals, and carefully staggered typography.
2. Active-line or active-word emphasis driven by existing lyric state.
3. A red thread that can become an underline, drawn stroke, crack, or transition.
4. Reusable graphic motifs that interact with text instead of appearing as unrelated stickers.
5. Connected scene transitions in which existing elements create or reveal the next composition.
6. Restrained rhythmic accents using existing beat data if available.
7. Multiple distinct compositions rather than repeating the same effect for every line.

The result must look like a motion designer created it, not like ordinary subtitles with random effects.

Use meaningful visual metaphors when appropriate. If semantic analysis or metadata is unavailable, use the template's designed typography treatments rather than making unreliable assumptions about lyric meaning.

Separate the implementation into logical components, such as:

Use the repository's actual framework and libraries.

Do not introduce Remotion, React, or a separate web rendering engine into a native Flutter app unless the existing architecture genuinely requires it.

Do not add unnecessary dependencies.

The template must accept live lyric data as input and render it without hardcoded production lyrics.

PHASE 4 — INTEGRATE WITH THE EXISTING LYRICS

Connect the finished template to the existing Lyrics section.

Requirements:
- Reuse the current lyrics provider and playback controller.
- Reuse existing lyric timestamps and active-line or active-word state.
- Keep the current music playback running continuously.
- Update animations in response to playback position.
- Handle pause, resume, seek, replay, and track changes.
- Handle lyrics loading, missing lyrics, and empty lyrics gracefully.
- Support Hindi/Devanagari, Hinglish, English, punctuation, and mixed scripts.
- Preserve correct Unicode shaping, conjuncts, and vowel marks.
- Avoid splitting raw Unicode characters in ways that break text rendering.
- Respect the existing app theme, navigation, screen size, and safe areas.
- Maintain smooth performance without unnecessary rebuilds.

If the app provides only line-level timing, synchronize at the line level. Do not invent word-level timestamps.

If lyrics are already synchronized, do not run forced alignment again.

Keep the existing standard lyrics experience functional. Add a sensible way to open or switch to the animated lyrics view without breaking current controls or navigation.

PHASE 5 — PERFORMANCE AND QUALITY

- Keep animation timing deterministic.
- Avoid expensive calculations on every frame.
- Cache reusable assets where appropriate.
- Avoid memory leaks and unnecessary animation controllers.
- Dispose of resources correctly.
- Respect reduced-motion or accessibility preferences where supported.
- Ensure the animation never blocks audio playback.
- Do not add backend infrastructure or AI services unless genuinely required.
